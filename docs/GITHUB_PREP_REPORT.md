## 3. Hardcoded local paths (`/Users/test/...`)

**Type of risk:** privacy leak (reveals local username and folder layout),
not a credential leak. Confirmed present in 20 files:

- `pipeline/config.py:36` — `IP_CHARACTER_DIR = Path("/Users/test/Desktop/character_look")`,
  a legacy fallback the file's own comment says is "only used when no look
  package is selected (generation is blocked in that case)." Low-impact but
  easy to fix.
- `project_state.json`, `project_state.last_valid.json` — pervasively, as
  absolute paths to every asset/output referenced in the run history.
- 16 files under `outputs/`, `storyboards/`, `docs/CODE_INVENTORY.md` (this
  report's own sibling doc, which quotes the path as an example — not a
  concern) — all generated/logged output referencing absolute local paths.

**Recommended but not applied** (per Step 4 — this is a behavior change,
not a comment/doc edit, so it is reported here rather than made):
`pipeline/config.py:36` could be changed to a relative or env-configurable
path (e.g. `Path(os.getenv("IP_CHARACTER_DIR", ROOT_DIR / "character_look"))`)
so the hardcoded username doesn't ship in the public repo. This is a one-line
code change I have not made, since it touches runtime path-resolution
logic. Your call whether to apply it before pushing.

`project_state.json` and `project_state.last_valid.json` are recommended
for `.gitignore` exclusion rather than path-scrubbing, since they're
regenerated by running the pipeline and contain the bulk of the path
leakage (see §5).
