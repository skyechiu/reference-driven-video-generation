Reference-Driven Agentic Short-Form Video Generation System

A single-character, reference-driven, package-controlled, storyboard-JSON-centred agentic video generation pipeline. It adaptively reuses the available structure of each reference shot — assigning a conditioning mode by how much reliable structure that shot provides — rather than applying one fixed strategy to every video. Handles multi-shot video, single-take key moments, and storyboard-prompt mode; high-energy driving performance is planned future work. All inputs normalise to generation_units[] then enter a unified IP-conditioned generation → evaluation → repair loop.

What this workflow is

Practical for short-form reference-guided regeneration — especially when the reference has clear shot structure, readable subject motion, and visually separable identity / look / scene components. After analysis, each shot is assigned a conditioning mode by the quality of its extracted structure, so the workflow reuses available structure adaptively across different reference videos — not one fixed strategy for every clip.

Scope boundary

The current API-based implementation is not designed for exact frame-level motion transfer or complex high-energy performance replication. It preserves shot structure and action intent — not pixel-level motion.

Core Components
🔍
Reference Analyzer
PySceneDetect · TransNetV2 · MediaPipe / DWPose · librosa · GPT-4o Vision. Extracts shots, pose, framing, beat, semantic labels.
📋
Template Builder
Converts analysis into beat-aligned storyboard JSON. Snaps cut times to nearest beat (max_snap_distance 150 ms). Outputs generation_units[].
🎨
IP-Conditioned Generator
LoRA / IP-Adapter + pose conditioning. GPT-image-1 for keyframes. Kling I2V for video. Generates per unit — never one-shot whole video.
📊
Evaluator
ArcFace identity score · keypoint distance · beat alignment error (ms) · framing accuracy · subject count · look score. View-adaptive profile per framing.
🔧
Repair Planner
Classifies failure reason → targeted fix: identity drift → stronger LoRA weight; pose mismatch → stronger pose ref; framing error → rewrite prompt; extra subject → stricter constraint.
📝
Decision Logger
Records every attempt: scores, verdict, diagnosis, repair_action, improved_from_previous. Terminal state needs_human after max retries. The agentic evidence for dissertation.
📦
Three Packages
Identity Package (who) + Look Package (appearance) + Scene Package (environment). All three travel through the entire pipeline alongside every generation unit.
🗂
project_state.json
Single central state file. All agents read and write here. Contains decision log per shot, config, reference_data, shots[], generation_units[], experiments[]. The pipeline's backbone.
Detailed Pipeline — Evaluation & Repair Loop

Strategy A / B / C above is the input-level router. Within a run, each shot is graded further by the Per-Shot Conditioning Router (pose · head-orientation · framing); Strategy C (dance / driving performance) is future work, not the current API build. The system reuses structure and action intent — it does not perform exact frame-level motion transfer.

Final Assembly
All passed units assembled in beat order → final 9:16 vertical short video output. Evaluation Report generated from decision log data.

Per-Shot Conditioning Router — graded strategy selection

Distinct from the input-level strategies above: within a run, each shot is routed to a conditioning mode by how much reliable structure it actually provides. Conditioning strength is graded — the number of usable body skeletons equals the number of clean full-body shots, no more. If the extracted structure is unreliable, the shot drops to weaker conditioning or human review. This is what lets the workflow reuse available structure across different reference videos without claiming exact motion transfer.

Evaluation Metrics
Identity Score
ArcFace cosine similarity vs reference embeddings. Phase 0 pass threshold defined pre-run.
Look Score
Perceptual hash + CLIP similarity vs look reference images. Hair / outfit / silhouette.
Pose Similarity
Keypoint distance (MediaPipe) between reference pose and generated frame.
Framing Accuracy
Detected bbox vs target framing label (CU / MCU / MW / Wide). YOLOv8 person bbox.
Beat Alignment Error
Cut timestamp offset from nearest beat (ms). Target ≤150ms snap threshold.
Subject Count
YOLO person count check. Single-character constraint: exactly 1 main subject visible.
Scene Score
CLIP similarity vs scene reference images. Environment, light, background match.
Regen Success Rate
% of failed units that pass after repair loop. Core experiment metric.
Repair Taxonomy
identity_drift
→ raise LoRA weight · add more identity refs
look_mismatch
→ strengthen look prompt · add look image refs
scene_mismatch
→ rewrite scene prompt · use scene_package refs
framing_error
→ rewrite framing constraint in prompt
pose_mismatch
→ use clearer source keyframe · stronger pose conditioning
motion_issue
→ re-run I2V only · adjust video prompt motion intensity
extra_subject
→ stricter single-character prompt constraint
body_deformation
→ shorten clip · reduce motion intensity · new seed
beat_drift
→ adjust cut timing · re-snap to nearest beat
Core Experiment

⬡ Loop OFF — Baseline

One-shot generation per unit. No retry. No repair. No diagnosis.

  • Identity average (ArcFace cosine)
  • Look average (CLIP)
  • Failed units count
  • Manual interventions needed
  • Attempts per unit: always 1

⬡ Loop ON — Auto-Repair

Auto-detect failures → diagnose → targeted repair → regenerate (max N retries).

  • Identity average (same metric)
  • Look average (same metric)
  • Failed units after repair
  • Manual interventions needed
  • Repair success rate
  • Avg attempts per unit
Both conditions use identical generation_units, packages, and prompts. The only variable is whether the evaluation→repair loop runs. Results feed directly into the dissertation Evaluation Report.
